# Verification — 0.0.4

Checked on 2026-09-25 on macOS using Python 3.9.6 (with the existing test environment's Paho/Tomli) and Python 3.14.7 (built-in tomllib). No real PBS server, MQTT broker, or SMTP service was contacted.

## Refactor verification

- Inspect the complete application and its existing tests/configuration/documentation before splitting responsibilities. Preserve the original entry-point filename and every prior release file.
- Compare all 24 original top-level functions/classes from 0.0.3 against their relocated definitions. Their ASTs match after normalizing only explicit module qualification and the local `settings` → `mqtt_settings` rename in notification dispatch. Each definition exists once; no duplicate implementations were introduced.
- Centralize version/root metadata in the package; validate both version markers are 0.0.4. Verify all eight Python files compile on both supported test runtimes, directing generated bytecode outside the project.
- Require both commented TOML files to retain all 43 schema/default values from 0.0.3, explanatory comments, and README coverage. The disclaimer matches the prior approved text byte-for-byte.
- Check every function/class appears in commented_code_map.md with its new owner file. Use real Git ignore checks to confirm all package sources and the example are trackable while private config files remain ignored.
- Execute actual help/version checks from another working directory on both runtimes, without config/log/notification side effects.

## Regression and integration checks

Run 30 offline tests from the final extracted ZIP on Python 3.9 and 3.14. The original 27 tests retain their behavioral assertions, with patches updated to the modules that own each dependency. Three new tests exercise:

- Direct and symlink invocation from another directory, importing the actual package and resolving config/logs beside the launcher rather than inside the package. Dry-run never invokes the fixture's PBS executable.
- Real CLI execution across module boundaries with a harmless fake PBS executable, testing success ordering, stopping at a simulated verify failure, full output capture, and error-only .err files. This is a subprocess integration test, not a real PBS operation.
- Independent import of every package module in a fresh process while subprocess creation and socket connections are forbidden. Imports do not create runtime logs or start work.

Existing checks cover manual-prune guards/arguments, disabled steps, output tails, configuration errors, dependency checks, MQTT/email dry-run combinations, notification independence, launch failure, private log permissions, SMTP modes and TLS failure handling. SMTP and MQTT delivery are mocked. Tests use disposable configs/logs, and the final extracted test copy omits ignored config.toml to also represent a Git checkout.

## Package verification

Check ZIP CRC integrity, exact member paths/bytes, manifest hashes, preservation of both original paths and all 13 prior-release paths, and inclusion of all six new package files. No runtime logs, bytecode, caches, environments, temporary files, or Git metadata are shipped. Source-file hashes are compared with the preserved original extraction because the original download ZIP is no longer at its original path. The immediate baseline is the verified complete 0.0.3 ZIP.

## Limits

Real PBS command compatibility, datastore effects, MQTT/SMTP delivery, production scheduling, concurrency, long-running output, interruptions, and full-disk conditions remain untested. The refactor retains existing limitations: no overlap lock, PBS command timeout, rollback, or independent task polling; unbounded captured output; five-second pipe-reader joins; and the original MQTT publish-wait/callback behavior. Unexpected failures can still end without notifications. See README for operational behavior.
