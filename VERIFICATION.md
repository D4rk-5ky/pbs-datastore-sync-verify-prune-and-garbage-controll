# Verification — 0.0.7

## Scope

- Immediate baseline: `pbs-datastore-sync-verify-prune-and-garbage-controll-0.0.6.zip`, SHA-256 `7398d9a86fc549114e306cfe604e968dc3a6c926775571926e504504ac39a4f8`.

PBS command construction/execution, prune safety, MQTT transport, sendmail transport, logging, dependencies and the launcher are otherwise unchanged.

## 0.0.7 behavior verified

- `mqtt.on_success` defaults to `false`.
- `email.on_success` defaults to `false`.
- A successful real run sends no MQTT/email unless the corresponding master channel is enabled and its `on_success` setting is explicitly `true`.
- A failed real run still sends MQTT when `mqtt.enabled = true`, regardless of `mqtt.on_success`.
- A failed real run still sends email when `email.enabled = true`, regardless of `email.on_success`.
- MQTT/email are still attempted independently; failure in one notification transport does not suppress the other.
- Dry-run semantics are unchanged: only `dry_run.send_mqtt` / `dry_run.send_email` select dry-run sends.
- Real-run preflight still validates enabled channels even when success sending is disabled, because those channels may be required for a failure report.

## Package verification

The final archive is built beneath one versioned top-level directory. Release checks verify ZIP CRC integrity, safe/non-duplicate paths, exact manifest file membership, manifest size/SHA-256 values, preservation of all 0.0.6 paths, and clean extraction. The extracted package is then used for a fresh `--help`, `--version`, Python-parse and full **33/33** offline test run.

## Limits

No real PBS datastore, MQTT broker, or sendmail/Postfix delivery endpoint is contacted by the offline suite. External service availability, actual PBS task completion semantics, production scheduling/overlap, interruption/full-disk scenarios, and end-to-end notification delivery must still be tested in the target environment.
